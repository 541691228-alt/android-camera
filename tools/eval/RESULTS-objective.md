## 一句话结论

主口径换掉。用 `J = r · c`（主体保留率 × 构图质量）替代 `kept_ratio`，`kept` 降级成诊断列。

换的理由不是"J 更好看"，是 `kept_ratio` 在 src 口径下有精确的退化解：候选集里它的最优框恒为整图，
9 个口径实测最优候选落在"最大框那一档"的比例是 src 的 100.0%（构造上必然）和固定比例口径的 99.4%~99.9%，
算法框在 src 上赢过"不裁"的比例 **0.0%**（三个数据集都是 0.0%）。也就是说，
"src 上算法丢主体输给居中"这条结论，一半以上是度量造成的，不是算法造成的。

换成 J 之后，"算法 vs 同尺寸居中"在 **9/9 口径**上都是算法大幅领先：+0.183 ~ +0.229（t = 20.5 ~ 54.0，
逐图胜率 51.2% ~ 78.9%），不再有负号。

同时要重述一条旧结论：J 口径下**两个权重（基线 0.55/0.25/0.20 与新权重 0.40/0.60/0.00）都远为正**，
新权重相对基线的增益很小——8/9 口径为正（+0.002 ~ +0.023），ECSSD src 上反而是 −0.002。
所以"新权重更好"不能靠这个度量立论，得继续靠整图框率、`capture_ratio`、切主体率这些读数（见第 6 节）。

## 1. kept_ratio 的退化解

记 S 为真值主体像素集，B 为裁剪框像素集，r(B) = |S ∩ B| / |S|。

对 src 口径（aspect = 原图比例），候选集里 `k = 0` 那一档就是整图框，于是

```
r(整图) = |S| / |S| = 1
∀B : r(B) ≤ 1 = r(整图)
```

整图框**弱支配**所有候选；当没有更小的候选框能装下全部 S 时（主体不贴边、不是整幅时就是这种情况），
它是唯一最优。这个性质和图像内容、显著度模型、权重都无关，是度量本身的性质。

后果有两层。第一层，`kept_ratio` 单独没法评价裁剪算法：算法一旦裁小，它的分数就要跟"自己什么都不做时的 1.0"比，
而"最大框居中"这种不做任何判断的解直接拿到满分。第二层，同尺寸居中对照天然占便宜：对照框的尺寸跟着算法走，
在主体本来就靠中间的图上，居中框的 r 不会比算法差多少，而算法裁小之后 r 必然掉。

src 之外的固定比例口径（1:1、3:4）里最大框不一定装得下全部主体，退化不彻底，但实测仍然几乎全部落在最大框上：

这解释了 `RESULTS-weight-sweep.md` 第 6 节那条"面积项归零必须和保留率权重提高同时做"——
面积项本身只会把解往"不裁"推。

## 2. 四个候选度量

统一记：`r` 同上；`d` = 主体质心到最近三分点的距离（框内归一化坐标，
与 `sweep_weights.thirds_dist` 同口径，不夹取）；`DMAX = hypot(1/6, 1/6) = 0.2357023`（画面正中到最近三分点）；
`c = clip(1 − d / DMAX, 0, 1)`；`S`、`B` 同第 1 节。

### M1 `J = r · c`

- 取值 [0, 1]。
- 无无条件退化解。反证：J = 1 要求 r = 1（框含全部主体）且 c = 1（主体质心正好落在三分点上），
  前者需要 S 的位置信息，后者需要 S 的质心信息，都不可能在"与图像内容无关的固定框"上同时成立。
  取一张 S 在画面右上角的图和一张 S 在左下角的图，同一个固定框不可能同时满足 r = 1。
- 实测它自己的最优候选也不塌陷：候选集 argmax 的面积 0.443 ~ 0.662、kept 0.815 ~ 0.943、
  thirds 0.011 ~ 0.026（9 口径），是"保住主体、把质心压到三分点上"的合理框，不是细长条。
- 弱点：c 只用质心，一个切掉大半个主体、但质心恰好落在三分点的框仍能拿到不错的 J。
  所以 J 必须和 r 一起读，报告里不能只给 J。

### M2 `H = 2rc / (r + c)`

- 取值 [0, 1]，H = 1 当且仅当 r = c = 1，同样无无条件退化解（理由同 M1）。
- 对 0 ≤ r, c ≤ 1 恒有 `H ≥ J`（H ≥ 几何平均 ≥ 乘积），所以 H 是 J 的**宽松**版本：
  均值更高、配对差略小，但方向、显著性、逐图胜率与 J 在 9/9 口径上一致（第 4 节）。
  适合当 J 的稳健性对照，不适合单独当头条数字。

### M3 `F = 2|S ∩ B| / (|S| + |B|)`（Dice / F1）

- 取值 [0, 1]，F = 1 当且仅当 B = S（像素集完全相等），没有无条件退化解；
  它的 optimizer 实测是一个贴合主体的紧框（面积 0.391 ~ 0.606、kept 0.941 ~ 0.983、thirds 0.138 ~ 0.151）。
- 但它**不能用来证明"换了度量"**。同尺寸对照时 |B| 固定，F = 2|S∩B| / (|S| + |B|) 是 |S∩B| = r·|S| 的严格单调函数，
  两个同尺寸框的 F 排序与 kept 排序逐位相同。实测 9 口径、base/new 共 18 组逐图胜率**逐位相等**
  （12.7/12.7、19.8/19.8、25.3/25.3、…、41.7/41.7），Δ 的符号也 9/9 相同。
- 它的用处是跨尺寸比较：不裁框因为 |B| 最大而吃到最重的 precision 惩罚
  （DUTS src：不裁 0.2377 vs 算法 0.2877/0.2967），正好把 kept 的偏好反过来。

### M4 `Rc = r · 1[d ≤ 0.10]`（构图约束下的保留率）

- 取值 [0, 1]。最优解既要 r 大又要构图达标，没有无条件退化解，但它有 14.5% ~ 43.1% 的图上
  最优候选仍是最大框（9 口径，见第 4 节表 D），退化只被压掉一半。
- 更麻烦的是阶跃：实测它的最优候选 thirds 停在 0.090 ~ 0.099，全都贴着阈值 0.10——
  只要刚好达标就拿满分，没有再往三分点靠的梯度。作为"构图是否达标"的读数可以，作为目标函数不行。
- 不推荐当主口径。

### 顺带排除的分量

`comp`（= c）忽略保留，可以给"质心在三分点上"但主体被切光的框打满分；
`thirds`（= d）同理；`area` 本身退化解（见第 1 节末）。这三个分量都只适合当诊断列。

**建议的报告头行**：`J`（主）、`H`（稳健性）、`kept`（切没切到主体的诊断）、`F`（跨尺寸贴合度）。`Rc` 不用。

## 6. 旧结论怎么重述

1. `RESULTS-weight-sweep.md` 第 1、5 节"src 口径下算法丢主体略输居中（−0.00587 / −0.01364 / −0.00227）"——
   这三条要整条重述。它们是 kept 口径的性质，在 J 口径下同一批图是 +0.199 ~ +0.226（t 24 ~ 49）。
   正确的说法是："算法在 src 上少保住了约 0.2 ~ 2.5 个百分点的主体像素，但把主体质心到三分点的距离
   压低了 0.05（相对基线自身约 50%）；旧口径只统计前者，所以读到的是输。"
2. 第 7 节"src 上出现差异的图里赢 993 / 输 1622（z = −12.3）"——这是 kept 的逐图统计。
   同一批图按 J 算，逐图胜率 55.4%（基线）/ 62.6%（新），不再是少数赢。
3. 第 10 行"把面积项权重归零、保留率权重提到三分线距离的 1.5 倍"这条建议不受影响，但要换个论据：
   J 口径下新权重只比基线好 +0.002 ~ +0.023（8/9 口径为正，ECSSD src 是 −0.002），
   单看 J 不足以支撑"新权重更好"。它的证据仍然在整图框率（31.6% → 21.2%）、
   `capture_ratio`（−0.114 → +0.326）、切主体率、死中率上。
4. `ceiling_check.py` 里"无约束上限在 src 恒 1.0，最大框＝整图，是退化解"这条注解，
   现在有量化证据了：候选集 argmax 100% 落在最大框档，算法赢过不裁框的比例 0.0%（9/9 口径）。
   这句注解可以从"提醒"升级成"依据"。
5. 新结论：**报数头行换成 J**，`kept` 保留为诊断列。以后凡是"算法 vs 居中"的对照，
   都要同时给 kept 和 J 两列，单给 kept 那一列会重复这一次的误读。
6. 副作用提示：J 与 H 在 ECSSD src / 1:1 上对新权重 vs 基线的名次不一致（差 0.002 ~ 0.006），
   这个尺度的结论不要写进报告。

## 7. 局限

1. J 与 H 都只用**质心**定构图，不看主体的形状、朝向、被切开的程度。
   一个切掉大半个主体、但残存部分质心恰好落在三分点的框仍能拿到不错的 J。
   实操上必须 J 与 kept 并列读（本脚本两个都输出）。
2. 主体占比很小时 r 容易接近 1，J 对"小主体框得好不好"不敏感。
3. 真值主体是人工标注的显著度 mask，不是"人真正想要的构图"。J 高只说明"保住了主体且质心在三分点上"，
   不代表构图讨人喜欢。审美那一层归 `aesthetic_score.py` / `pref_eval.py`。
4. 全部评测建立在 u2netp 64×48 显著度网格上（与已发布口径一致）。换模型或换网格要重跑，
   生成脚本接的仍是 `sim_bestcrop.image_features`（Lead 已给 cols/rows 可选参数，默认 64×48 行为不变）。
5. 同尺寸居中对照对 J 最不利：居中框的构图项天然差。表 C 已经给更严的"最大居中框"对照补上了，
   结论方向不变（src 50.6% ~ 62.1%，1:1/3:4 71% ~ 79%），但 src 上的优势确实小一截。
6. 表 B 里 ECSSD 1:1 的新权重 vs 基线三个读数互相矛盾，本轮没有解决；如果要给新权重一个稳健的优势证据，
   应该在 J 之外补一个不依赖质心的构图项（例如框内主体的分散度，或用 IoU 加权的三分点得分），本轮没做。
7. J 也会被"兜底框"（src 下就是整图）刷高：J(整图) = comp(整图)，主体本来就贴三分点的图上它天然得高分。
   实测 src 上"兜底框 J ≥ 算法框 J"的图片占比是 44.5% / 37.9%（DUTS 基线 / 新）、43.9% / 38.9%（ECSSD）、
   49.4% / 40.5%（DUT-OMRON），即约四成的图不裁也不吃亏。所以 J 不能单独报，必须与兜底率、三分线距离
   并列读（表 A2）。这是 J 相对 kept 的改进（kept 在 src 上是 0% 对 100%），不是"J 没有短板"。
8. 凡是把 `1 − kept` 当分母的比值都不稳定，不要拿它当度量。单图上 `(1 − kept_居中) / (1 − kept_兜底)`
   可以取到 44.75（ECSSD 3:4）、127.80（DUT-OMRON 1:1）、3465（DUTS 1:1），因为 `kept ≈ 1` 时
   分母趋于零、比值被少数像素放大。要衡量"裁剪是否值得"，用 J 的配对差，不要用这类比值。
   这三个数只作数量级说明：极值对分母口径（居中框 / 兜底框 / 各度量自己的最优框）与数据集都很敏感，
   实测横跨 10¹ ~ 10³，不要当稳定数字引用——同一个式子换一列分母就能从 44.75 跳到 3465。
