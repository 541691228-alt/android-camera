# 反推 bestCrop 评分权重：把"丢主体输给居中"这条翻正

- 日期：2026-10-05
- 数据集：DUTS-TE（5019 张）、ECSSD（995 张）、DUT-OMRON（5123 张）
- 评测口径：`tools/eval/run_eval.py` 的聚合定义（保留率、配对差值、配对 t、三分线距离、切主体率、整图框率、裁剪面积、死中率）
- 本轮**只做离线评估，没有改动任何生产代码**（`app/src/main/java/cn/yege/dshcam/AutoFrame.kt` 一行未动）

## 一句话结论

把评分里的**面积项权重归零**、把**保留率权重提到三分线距离权重的 1.5 倍**（推荐 `w_thirds = 0.40 / w_ret = 0.60 / w_area = 0.00`，两件事**缺一不可**：只归零面积项反而更差，见第 6 节第 1 条），
原先"算法保留率略输居中"的 4 个亏空口径都补上了：**3 个明确翻正**（差值从 −0.0059 / −0.0011 / −0.0023 变成 +0.0047 / +0.0238 / +0.0147，t = 4.7 / 8.2 / 10.2），
**ECSSD src 从 −0.01364 补到 −0.0006（t = −0.43，即补平到不显著的零附近，该数据集上只能说"不再输"）**；
其余 5 个本来为正的口径也同向变大。`capture_ratio` 从 **−0.114 变成 +0.326**，整图框率与裁剪面积同步下降，
代价是三分线距离最多变差 0.003（相对算法自身值约 3%）、切主体率 ±2 个百分点。

两个限定必须一起说（第 5、7 节）：
① 均值改善**靠少数大幅赢的图**——src 上出现差异的图里输的仍多于赢的（993 / 1622），只有 3:4 是多数赢；
② 换成更严的对照（居中框取该比例的**最大框**）后，**只有 3:4 仍稳赢**，1:1 仍差 0.0065（但比基线好 2.4 倍），src 必输（最大框＝整图）。

## 1. 问题

已发布的评测结论是：**构图改善站得住，但 src（原图比例）口径下算法丢主体略输居中**——

| | 算法 | 居中 | 差值 | 配对 t |
|---|---|---|---|---|
| DUTS-TE src | 0.972673 | 0.978546 | **−0.00587** | −7.03 |
| ECSSD src | 0.970265 | 0.983904 | **−0.01364** | −9.96 |
| DUT-OMRON src | 0.970430 | 0.972703 | **−0.00227** | −2.02 |

于是提出一个问题：**不动候选生成、不动显著度模型，只改 `AutoFrame.scoreCrop` 那三个权重，能不能把这条翻正，而且不牺牲已经拿到的构图收益？**

## 2. 方法

1. `tools/eval/sim_bestcrop.py` —— 把 Kotlin 的 `bestCrop`/`scoreCrop` 逐位搬到 Python。
   **保真性证明**：对 5019 张图 × 6 种调用口径（src / 1:1 / 3:4 / ABS 门槛 0.0001 / RANGE 门槛 0.30 / 锚点 12），
   逐行比对裁剪框，**全部 0 不一致**（单口径 1.7 秒；Kotlin harness 同样一盘要 2 分 10 秒）。
2. `tools/eval/sweep_weights.py` —— 把候选框特征与权重**解耦**：每张图只算一次候选特征（6 张积分图）
   与一次掩膜积分，然后对**一整批权重**同时算分数矩阵（float32 外积 + 切分惩罚），所以加一组权重几乎不额外花时间。
3. **聚合保真性**：用基线权重（0.55 / 0.25 / 0.20，onset 0.75，slope 1.6，`gate_rel` 0.05，`keep` 0.60，aspect src）
   跑扫参器，三个数据集**逐位复现已发布报告**（DUTS-TE 0.9727 / 0.9785 / −0.00587 / t −7.03 / 三分线 0.0951 / 切主体 31.1% / 整图框 31.6%；
   ECSSD 0.9703 / 0.9839；DUT-OMRON 0.9704 / 0.9727；n = 5019 / 995 / 5123 也一致）。

> 调用配置与生产一致：`CameraController.kt:583-585` 用的是
> `AutoFrame.bestCrop(shown, shownW, shownH, shownW/shownH, 0.60f)` ——
> 比例＝原图比例、`minKeep` 0.60、默认 ABS 门槛 0.05、锚点 0。扫参用的就是这一组参数。

## 4. 推荐

**首选 `w_thirds = 0.40 / w_ret = 0.60 / w_area = 0.00`**：

- 主要口径（DUTS-TE src）上 **基线被完整支配**：差值 −0.00587 → +0.00469（t −7.03 → +4.70），
  三分线距离还略好（0.0951 → 0.0949），整图框率 31.6% → 21.2%，裁剪面积 0.752 → 0.718，死中率 3.5% → 3.0%；
  唯一变差的是切主体率 31.1% → 32.7%（居中对照是 23.6%，两者都高于它）。
- 另外 8 个口径全部同向改善（唯独 ECSSD src 是 −0.01364 → −0.00064，**补平但仍差 0.0006、不显著**），
  且是新权重族里**最保守**的一点（裁剪面积最大、切主体率最低、三分线最好）。
- 若要求每个口径都"非负"，再往保留率一侧挪一点即可：`0.35/0.65/0.00` 让 ECSSD src 变成 +0.00043（t = 0.32）、
  `0.30/0.70/0.00` 变成 +0.00107（t = 0.88）；但两个都是**不显著的正**，且 DUTS-TE src 的三分线距离会从 0.0949 退到 0.0974 / 0.1014。
- 想要更高保留率可退到 `0.33/0.68` 或 `0.30/0.70`：DUTS-TE src 上差值再涨约 0.0004，但三分线距离要付 0.002 ~ 0.006。
- **最优区很平，别把具体数字当精确解**：3 折交叉验证里折内挑出的最优权重落在 `0.25/0.75` ~ `0.40/0.60` 之间，
  折外差值（src +0.00432、1:1 +0.02589、3:4 +0.04873）说明这一族都有效；选 0.40/0.60 的理由是它在**保守性**上最好（面积最大、切主体最低、三分线最好），不是因为它差值最大。
- **落地时的取舍点**：如果更在意"多数图别变差"，往 `0.30/0.70` 走（3:4 上多数图是赢的）；如果更在意"别切主体"，`0.40/0.60` 就已经是这一族里最保守的。

## 5. 独立复验（反证尝试）

复验脚本 `tools/eval/verify_weight_sweep.py` **不走扫参器的聚合代码**：它用 `metrics.py` 重算逐图指标、用 `sim_bestcrop.py` 重新出框，再把框导回**已发布的** `run_eval.py` 聚合。

1. **数字逐位复现**：三个比例下重算的差值与原扫参 JSON 完全一致（src −0.00587 / +0.00469；1:1 +0.00751 / +0.02557；3:4 +0.02434 / +0.04533）。
2. **配对 bootstrap（10000 次）**：基线 src 的 95% 区间 [−0.00750, −0.00421]、新权重 [+0.00277, +0.00667]，都不跨 0；
   1:1 新权重 [+0.02161, +0.02965]；3:4 新权重 [+0.03998, +0.05055]。
3. **3 折交叉验证**（折内挑最优权重、折外验）：折外合计 src **+0.00432**、1:1 **+0.02589**、3:4 **+0.04873**，
   没有"只在挑参数那份数据上好看"的塌陷；折内挑出的权重落在 0.25~0.40，说明最优区很平。
4. **符号检验给出一记反调**：src 上出现差异的图里，新权重 **赢 993 / 输 1622**（z = −12.3；基线 637/1588，z = −20.2）。
   即**均值变正是靠少数大幅赢的图**，多数有差异的图其实略输；1:1 赢 1652 / 输 1901（z = −4.2）；只有 3:4 是真的多数赢（2034 / 1817，z = +3.5）。
   这条必须和均值一起看——win/tie/lose 从 12.7/55.7/31.6 变成 19.8/47.9/32.3（赢的比例涨 7 个百分点，输的比例几乎没动）。
5. **换更严的"居中"对照**（居中框取该比例的**最大框**，而不是跟算法框同尺寸）：

   | 口径 | 基线 同尺寸 / 最大框 | 新权重 同尺寸 / 最大框 |
   |---|---|---|
   | src（最大框＝整图） | −0.00587 / −0.02733 | +0.00469 / −0.02468 |
   | 1:1 | +0.00751 / −0.01579 | +0.02557 / −0.00645 |
   | 3:4 | +0.02434 / +0.00414 | +0.04533 / +0.01923 |

   src 口径下"最大居中框"就是整图，任何裁剪算法都不可能赢；1:1 上新权重在更严口径下仍差 0.0065（基线差 0.0158，改善 2.4 倍）；3:4 上仍为正。
   **结论：已发布口径（同尺寸居中）成立，换成最大框居中后只有 3:4 稳赢。**
6. **消融推翻了"面积项单独归零就能翻正"这个说法**——见下一节第 1 条，已按实测改写。

## 6. 结构发现（比"换个数"更重要）

1. **两个改动必须同时做，缺一不可。** 只把 `w_area` 归零、比例照旧（`0.55/0.25/0.00`）**反而更差**：
   src −0.00745（基线 −0.00587）、1:1 +0.00559（基线 +0.00751）、3:4 +0.02298（基线 +0.02434）。
   两个原因：分数整体变小，而采纳门槛是绝对值（0.05），相对更难越过；三分线占优会把框收到"构图好看但切主体"的小框（src 切主体率 31.1% → 47.7%）。
   反过来只抬保留率、留着面积项（`0.25/0.55/0.20`）也不行：面积项给最大框白送 +0.20，实测 src 上**采纳率 0%、差值恰好 0.00000**（全部回退"不裁"）。
   真正起作用的是组合拳：**面积项归零（否则"不裁"是默认答案）＋ 保留率权重压过三分线（否则裁剪过度、丢主体）**。
   （生产代码里 2026-10-05 那条"罚分过重、面积项过大导致算法从不生效"的注释，方向是对的，但当时的解法是放宽 `minKeep` 0.85 → 0.60，没动权重。）
2. **切分惩罚不是独立维度。** `cutPenalty = (onset − retention) × slope` 只是 retention 的线性函数：
   在 `retention < onset` 段，它等价于"把 `slope` 加到 `w_ret` 上、再整体减一个常数"。
   实测 onset 0.5~0.9 × slope 0~8 × 3 组基础权重共 **126 组，结果完全相同**（8.4 秒跑完）。
   也就是说这一项可以删掉，它想做的事已经被保留率权重做完了。
3. **权重的绝对尺度也有影响**，因为采纳门槛是绝对值（`margin = gate_rel = 0.05`）——
   权重整体放大就更容易越过门槛。DUTS-TE src：`0.15/0.35/0` → −0.00132（t −4.04，整图框率飙到 81.7%，几乎不裁）；
   `0.30/0.70/0` → +0.00501（整图框 32.2%）；`0.60/1.40/0` → +0.00866（16.0%）；`1.20/2.80/0` → +0.00998（9.9%，但切主体率升到 32.5%）。
4. **`gate_rel` 才是"敢不敢偏离居中"的总开关。** `0.40/0.60/0` 在 DUTS-TE src 上：
   `0.02` → +0.00702（整图框 9.5%）、`0.05` → +0.00469（21.2%）、`0.10` → +0.00010（51.1%）、
   **`0.20` → 0.00000 且整图框率 100%**（所有图都判定"不采纳候选"，全部回退居中框，算法退化成居中裁剪）。

## 7. 局限

- **均值改善由少数"大幅赢"的图驱动**：src 上出现差异的图里输的仍多于赢的（993 / 1622），是新权重在少数图上多救回很多主体把均值拉正的。
  如果关心的是"多数情况别变差"而不是"平均更好"，这个改动在 src / 1:1 上并不满足（3:4 上满足）。
- **ECSSD src 只做到"不输"**：−0.01364 → +0.00107，t = 0.88，不显著；在这个数据集上"翻正"的把握不足，只能说把最大的亏空补掉了。
- 只调了评分权重，**没动候选生成**（21 档 scale、`stepX/stepY`、锚点）——那部分还有空间，本轮没碰。
- 全程离线网格评测（64×48 显著度网格），**没有上真机、没有打 APK**；结论只在数据层，真机观感待验。
- 三分线距离是最朴素的构图代理指标（主体质心到四个三分点的距离），它变差 0.002 ~ 0.003 是否等于"构图变差"，需要人眼确认。
- 离群个案（全量 11137 张里 21 张，0.19%）的根因是**标注与模型的语义分歧**（标注只标小物体、模型选了另一个大物体），权重解决不了，仍然存在。
