## 1. 方法与口径

**评测链路（与 `sweep_weights.py` / `sim_bestcrop.py` 同一条代码路径，未改共享代码）**

1. 显著度模型 → 每张图的 64×48 显著度网格（`model_grid.py`，落盘 `grids.bin` 大端 f4 + `grids_manifest.tsv`）。
2. 网格 → 候选裁剪框（`sim_bestcrop.image_features` / `build_candidates`，21 档 scale，`EVAL_MIN_KEEP=0.60`）。
3. 打分 `SC = 三分线×0.40 + 保留率×0.60 + 面积×0.00 − max(0, 0.75−保留率)×1.6`，取 argmax。
4. 采纳门 `ABS_GATE_MARGIN=0.05`：仅当最优候选比"最居中候选"得分高 ≥0.05 才采纳，否则回退到最居中框（本文记作**兜底**）。
5. 指标：把 GT 掩膜（像素 ≥128 为前景）积分后，量算法框的**保留率 A**、与之同尺寸**居中框保留率 C**、Δ=A−C 及逐图配对 t、前景质心到最近三分点的距离、**切主体率**（保留率 <0.99）、**采纳率**、**裁剪面积比**、**兜底率**、三分线距离。
6. **完美先验 B**：把 GT 掩膜自身当作显著度网格（`oracle_prior_check.perfect_grid`，64×48 BOX 下采样）走同一条打分/采纳链路。B 与模型无关，每个数据集×口径只需算一次。**B−A 即"该模型离完美显著度图还差多少"**，也就是显著度模型层的剩余提升空间。
7. **去兜底保留率 A_ns**：只在"未命中整图兜底"的图上重算保留率。整图框天然保留率≈1.0，会系统性抬高 A（例如 OMRON src 上 RMBG-1.4 兜底率 40.0%、u2netp 23.0%），所以 A_ns 与 A 一起看才公平。
8. **中位 IoU（64×48）**：模型网格二值化 >0.5 与 GT 缩到同分辨率的逐图 IoU 中位数；这一列是**排行榜内部一致**的量，不等同于"原生分辨率 IoU"（见 §6 probe 表：u2netp 原生 0.8326 vs 网格 0.8474——注意两者口径与 n 都不同）。

**口径**：`src` = 原图宽高比；`1` = 1:1；`0.75` = 3:4。三个口径都跑，主结论以 `src` 为准（与产线 AutoFrame 的默认路径一致）。

## 4. 「换更强显著度模型值多少」——按完美先验的可提升空间折算

## 7. 局限

1. **口径依赖**：主结论（RMBG-1.4 领先）只在 src 口径成立；1:1 / 3:4 下优势消失，OMRON 3:4 下反转。若产线要支持窄画幅，需按口径分别决策。
2. **64×48 网格是共享瓶颈**：所有模型都被降采样到 64×48 再评测，1024² 模型的边界优势会被抹平，B−A 的"剩余空间"也被这一量化误差污染。
3. **兜底混淆**：整图兜底保留率≈1.0，会把 A 抬高；本文用 A_ns 与兜底率两列对冲，但修正不完全（兜底与图像难度相关，非随机缺失）。RMBG-1.4 在 OMRON 上 40% 兜底率意味着它的 src 优势有相当部分来自"放弃"。
4. **ISNet / BiRefNet_lite 只用 600 张子集**：ISNet 是既定范围决策（选项 A，只跑子集）；BiRefNet_lite 是生成成本所迫（实测 3.2~5.4 s/格，全量 5019 张需 ≈4.5~7.5 h，且峰值内存 11.7 GB）。**两者的 600 子集数字不得与全量数字并排比**；已用同子集基准（§5）控制偏差（同集全量 vs 子集差 ≤0.002）。若后续要全量，只需补网格再跑同一 `run` 命令。
5. **t 检验按图独立**：同一数据集的图之间可能相关（同源摄影风格），t 值偏乐观，仅用于"是否显著非零"的粗判。
6. **单机 CPU**：所有耗时都是本机 CPU（`--threads 4`，且部分测量期间有其它生成任务在跑），不是移动端实测；产线端耗时需另测。
7. **未做**：APK/真机验证（用户明确要求只走理论线）、掩膜阈值（≥128）敏感性、每模型多阈值 IoU、模型集成。
